# Commvault MySQL iDA

Commvault's MySQL iDA simplified the end-to-end protection in
[MySQL](202607191021.md) while supporting full system and granular recovery of
data.

It supports database backup, transaction log backups, advanced MySQL server
restore capabilities, automatic discovery of apps, efficient job management and
reporting, backup and recovery [failovers](202607261833.md), and block-level
backups. Having block-level backups could back up extend or modification of
database instead of full database backup, which is faster.

Advanced MySQL server restore capabilities include full and partial restore,
restore and replay transaction log, set database state during restore,
Point-in-Time recovery.

If MySQL is installed in a Docker container, make sure that its binary path,
[socket](202211080912.md) file, log data directory, and configuration file are
exposed. To check them

For Linux:
-

- `mysqld --verbose --help | grep 'datadir\\|mysqld.sock\\|.cnf'` to get
  the configuration file, log directory, and socket file or endpoint.
- `which mysql` to get the binary path

For Windows:
-

- `Get-WmiObject win32_service | ?{$_.Name -like '*mysql*'} | select Name,
  PathName | fl` to get the binary directory and the configuration file
- `{binary path} --verbose --help } select-string -pattern "port", "datadir"` to
  get the log directory and port used

Make sure to update the Unix group after the client installation. We can check
this through the file `cat
/etc/CommVaultRegistry/Galaxy/Instance001/Base.properties | grep GalaxyGroup`.
