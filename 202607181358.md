# Oracle Database States

[Oracle Database](202607152254.md) has four states:
- **Shutdown**: all services stop
- **Started**: services running
- **Mounted**: [Control File](202607152300.md) read
- **Open**: data files and online redo logs open

They correspond to the commands within the interactive session, where we can
manipulate the state of the database:
- `shutdown` for *Shutdown*
- `startup nomount` for *Started*
- `startup mount` for *Mounted*
- `startup` for *Open*

In Started state, the database will read the [Parameter File](202607152311.md)
for database initialisation.

In Mounted state, the database will become aware of data files, [Transaction Log](202607160007.md),
backups etc. through [Control File](202607152300.md). Although the control file
contains the metadata about the location of the data files, thus making the
database aware of them, it does not fully aware of the content of the data files
since it only knows about the metadata of those files. In this state, the
database is eligible for offline backup.

To check the current database state, we can enter an interactive session by
running `sqlplus / as sysdba`, then run the query `select instance_name,
status from v$instance`. The state of the database is shown under the column
`status`. Note that we can get the `ORACLE_SID` ([Oracle SID](202607182147.md))
from the column `instance_name`.

In the case when the database state is shown as UNKNOWN when using
[Commvault](202607181352.md), we should assume that the permission is not set
correctly during the installation or the permissions have been modified since
then. Fixing this is as simple as running `cvpkgchg`. Refresh the properties
again before further troubleshooting.

Other than these four states, we could use [RMAN](202607180001.md) to set the
database into [Special Started State](202608121953.md).
