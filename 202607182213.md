# Commvault Oracle Database Backup Sequence

In [Oracle Database](202607152254.md), when doing a backup other than pure
archive log backup, [Commvault Oracle iDA](202607182207.md) follows particular
steps to ensure all data files, [SP file](202607152311.md), [Control
File](202607152300.md), and [archive logs](202607160007.md) are included as a
single job.

First, it will back up the *SP file and all data files*, then the *control file*
that contains the metadata for the data files that were being backed up. This
means that the first control file is aware of the data files. However, if the
backup job stops here, the continual changes made to the database during the
backup **would not be included** in this simple backup, increasing the RPO,
which is not desirable.

Thus, the job continues by backing up the *archive logs* so far, up until when
the first control file was backed up. Then, it backs up the *control file* once
again. This time, the control file is aware of the archive logs and the data
files, making the backup truly complete. This means that there will be **two
control files** for a single backup.

When doing a restore, always use the second control file.
