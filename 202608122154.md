# Commvault Oracle Database Channel Allocation Failure

One of the common issues in [Oracle Database](202607152254.md) backup is the
failure of channel allocation. It usually comes from the failure of loading the
[vendor library](202608122032.md) provided by [Commvault](202607181352.md). Due
to the different nature of various #operating-system, we have to approach the
issue in different ways.

It is recommended to run `sbttest` (usually found in `$ORACLE_HOME/bin/sbttest`)
before escalate to L2. See more in [sbttest](202608122210.md).

## Unix

On Unix system, channel allocation failure typically arise from permission
problems or wrong word size of the vendor library. The former can be solved with
the command `cvpkgchg`. To check the word size of the library, there are two
ways: one is by checking the `libobk.so` with `file` command, and another is
by login into [Recovery Manager (RMAN)](202607180001.md)/[SQL
Plus](202607172338.md), which will show something similar to "64bit Production"
(for 64 bits) or "Production" (for 32 bits).

## Windows

On Windows system, channel allocation issue does not occur at the time of the
backup since `backup.out` would not show the `SBT_LIB` argument. It means
that the system would not show where and what `orasbt.dll` is being used for
the [Commvault Oracle iDA](202607182207.md). This is because Oracle searches
the path for `orasbt.dll` only when its services are started, and adopt the
first result it can find for the runtime. If `orasbt.dll` is not found when
backing up, the channel allocation will fail. If instead it found the library
file of another vendor, the communication will break down soon after the
allocation of the channel if not during. Take note that if Commvault system
software is not named in the [log file](202607180018.md) alongside with its
version, it is clearly a system path issue.

First, verify the path with `cat env:PATH`, then verify the library file by
running `where.exe orasbt.dll`. If the file is not found, make sure the path is
set right, which is typically on `C:\Program Files\Commvault\ContentStore\Base`.
If the file is found but is not the first result from `where.exe`, we have to
either reorder the path precedence or rename other library files (shown by
`where.exe`). Renaming the other library files is the easiest solution, which is
recommended. Reordering the path requires a restart from the Oracle services to
recognise the new library file. To do that, we have to first compare the
installation time with the Oracle service start time with the command `gps -name
oracle | select name, starttime`.
