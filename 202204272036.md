# Ansible Playbooks

Playbooks are YAML files that are used for #[Ansible](202204272021.md)
configuration. Structurally, it contains plays, [variables](202205042134.md)#,
[modules](202204300820.md)#, and [plugins](202204300825.md)#. They could be
run by the command line `ansible-playbook` or #[content navigator](202204300954.md).
It is shown as below:

```yaml
--- # start of a play
- name: install and start apache
  hosts: web  # individual host or group
  become: yes # This is a plugin that escalate privilege (root permission)

  vars: # define variables for a play, not recommended
    var1: Ansible
    var2: This is
    var3: "{{ var2 }} {{ var1 }}" # Result: This is Ansible

  tasks:  # From here, define tasks
    - name: httpd package is present
      ansible.builtin.dnf: # This is a module
        name: httpd
        state: latest
      debug:  # Debugging messages
        msg: "some debugging messages"

    - name: latest index.html is present
      ansible.builtin.template: # This is a module
        src: files/index.html
        dest: /var/www/html/

    - name: httpd is started
      ansible.builtin.service: # This is a module
        name: httpd
        state: started
```

The order of the tasks written in the playbook is their order of execution. If a
task failed, the default behaviour will be to abort the rest of the playbook for
the host, then continue to the remaining hosts.

In the play section, we could add `role` to import [roles](202205042207.md)#. If
we just need that role for a task, we could include it using `include_role`
under `tasks`.

**Note**: Plays in a single playbook should be related.

**Note**: It is the best practice to use **fully qualified collection name**
when calling a [plugin](202204300825.md).
