# Ansible Inventory

Inventory is a list of nodes, where #[playbooks](202204272036.md) run against,
managed by #[Ansible](202204272021.md). Ansible has a default inventory file
`/etc/ansible/hosts`, but it could be changed using the option `-i`. We
could create multiple groups that can contain multiple hosts either in domain
name or [IPv4 address](202206151453.md)# within an inventory.

**Note**: Although Inventory could be used to store
[variables](202205042134.md)#, it is advised to only define them if they are
necessary for device connection such as user password and mean of communication.

There have two ways to define an inventory: static and dynamic. A static
inventory is text-based configuration which typically in INI or YAML format.
~Some are in a service or in git repository~. Dynamic inventory is, instead,
defined using [Ansible Plugins](202204300825.md) by utilising external
information providers or databases. The following configuration shows how a
static inventory can be defined:

```ini
[webservers]  # webservers group
b2bwebprod1 urlpath=https://b2bprod.abc.xyz
b2bwebprod2 ansible_host=10.100.25.3  # set name for IP address 10.100.25.3
b2bwebprod3 ansible_host=10.100.25.4  # set name for IP address 10.100.25.4

[appservers]  # appservers group, contains both IP addresses and domain name
10.25.13.25
10.40.12.44
b2bappprod1
b2bappprod2
b2bappprod3

[frontend:children] # parent group for group webservers and appservers
webservers
appservers
b2bslavedb

[webservers:vars]   # define group variables for webservers group
server_path=/var/www/html

[all:vars]          # define variables for all groups
user_name=ansible
ssh_key=/home/clover/.ssh/ssh.rsa
```

It is recommended to organise hosts into multiple groups based on the role,
physical location, whether it is in production environment etc. This would help
[plays](202204272036.md) to be applied according to their characteristics,
purpose, and location. However, we have to be cautious on group's name as having
the same name with a defined host will cause warnings from [command line tool](202204300954.md).
Thus, it is better to have different names for host and group.

Ansible's language provides syntax sugar for host specified range that comes
with `[start:end]`. The range can be in numerical or alphabetical, and in some
cases included [IPv6 Address](202206281129.md) range. The following
configuration shows how such syntax can be written. Note that leading 0(s) is
used as padding or pattern.

```ini
# IPv4 range/numerical
192.168.[4:7].[0:255]

# numerical with leading 0
server[01:20].example.com

# alphabetical
[a:c].dus.example.com

# IPv6 range
2001:db8::[a:f]
```

**Note**: In the case of `server[01:20].example.com`, the inventory will not
match `server7.example.com` as it has to match the leading 0, that is `07`.

**Note**: By default, #[Ansible](202204272021.md) use
[Domain Name Server (DNS)](202209300947.md)# for name lookup. This could be
circumvented by using the option `ansible_host` where custom name is assigned to
an IP address.

**Note**: Using keyword `children` after the group name impose a hierarchy of
groups. Such group can contain both groups and hosts.

**Note**: There are two default groups defined in Inventory: `all` and
`ungrouped`. The name of the groups should be self-explanatory.

**Note**: Using keyword `vars` after the group name define
[group variables](202205042134.md) which are only be used for that group.
However, if the name before the keyword is `all`, the variables could be used by
every group or host in the Inventory.
