# Commvault Oracle Database Missing Archive Log

Missing [archive logs](202607160007.md) from the disk is one of the common
issues in [Oracle](202607152254.md) backup. If the archive log file is lost, no
restore can be run to any point-in-time from this archive log until the next
data backup. This is because it is not the responsibility of [Recovery Manager
(RMAN)](202607180001.md) to look for missing archive logs.

Take note to the indicators **source** and **process** when we are
troubleshooting such issue through log files or via status report.

To not create recovery holes, we have to get the missing file back as soon as
possible in order to run the backup completely. We should utilise the RMAN
command `crosscheck` unless the log was accidentally moved to another location
or renamed or backed up by a file system backup. The following commands show how
should this be done. See more in [crosscheck](202608122212.md).

```
... > rman target /
RMAN> crosscheck archivelog all
```

In the case when the archive logs are moved to another file system due to
storage shortage, it is possible to move the logs back to their original
location. It is recommended to move them in small chunks to not risk filling up
the disk, then run `crosscheck` follow by [ArchiveLog Backup](202608102055.md)
for each chunk. This workflow avoids recovery hole while at the same time
keeping the database online.

If the databaes is running out of space, Oracle will revert to [Mounted
state](202607181358.md). Logs can still be backed up, but log switch cannot be
done in this state. This should not be an issue as archive log subclient by
default disable the option *Switch Current Log*. After the log has been backed
up, it should free up the space and bring the database online.
