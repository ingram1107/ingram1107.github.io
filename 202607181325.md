# RMAN Script

Within [RMAN](202607180001.md) script, there are several commands and
configurations worth looking at when troubleshooting.

`TRACE 0` indicates a debug level of 0. It has the maximum value of 2.

`backup param` indicates the incremental level for the backup, where a **value
of 0** represents a **full backup**.

`fileperset` represents the set's size. See more in [Recovery Manager (RMAN)](202607180001.md).

`format` is the naming scheme for piece handle(s), that is the name for backup
set.

`database` indicates that the script is going to perform a data backup.

`include current controlfile spfile` indicates that both [Control File](202607152300.md)
and [SP file](202607152311.md) should be included for the backup. This is
redundant when the script is told to perform an auto backup.

`sql` allows RMAN to execute [SQL Plus](202607172338.md) commands. For
example, with the command `sql "alter system archive log current"`, it can
archive the current online [redo log](202607152301.md) and start a new one.
This ensures that the [archive logs](202607160007.md) cover the transactions
right *up to the completion of the data backup.*

There may also involve logs backup options which is important to understand the
nature of it. Let's look at the following two examples:
- `(archivelog all delete input)` directs RMAN to archive all archive
  logs and delete those which were backup up as part of the job, and
- `(delete all input)` presents a different behaviour where all logs will
  be deleted regardless of whether they are backup up now.

Other examples such as `(archivelog all not backup three times)` involves
advance options set by the users.
