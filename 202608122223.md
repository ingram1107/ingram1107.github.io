# Commvault Oracle Database Restore Without Autobackup

If [Auto Backup](202608122010.md) is disabled and [Recovery
Catalogue](202607180014.md) is used, [Data Restore](202608121923.md) shouldn't
be an issue as [Control File](202607152300.md) is not typically necessary.
However, if catalogue is not used, we should check if the control file backup is
enabled.

Run `./getbackupList -jobid {} -outfile {} -dbjob` to get the file handle from
the output file. If [SP file](202607152311.md) is not backed up, then the file
handle of the control file should be shown at the last row. If SP is backed up,
then it should be shown at the second to last row. See [Commvault Oracle
Database Backup Sequence](202607182213.md) for the reason the second control
file is chosen.

If the job is recent enough an easier way to find out control file's piece
handle is by viewing `backup.out` from [RMAN log](202607181325.md).

If the backup in question was both data and logs, it will have two control files
backups. Choose the latter one.

[SQL Plus](202607172338.md) could also be used to query control file backup
using job ID, which is shown as follows:
```sql
alter session set nls_date_format = 'YYYY-MM-DD HH24:MI:SS';
column handle format A50;
select handle, start_time from v$backup_piece_details where bs_key in (select btype_key from v$backup_controlfile_details) and handle like '60688%');
```
